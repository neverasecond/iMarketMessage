# v0.2.0-beta 发布候选计划

目标是让愿意从可信源码构建的 macOS 用户获得一个可拖入 Applications 的 `iMM.app`，并能在本人明确授权后收到本地通知和启用后台检查。它仍不冒充 Developer ID 签名、公证或 Mac App Store 产品。

## 已进入开发分支

- `scripts/build-local-app.sh` 构建标准 app bundle、嵌入 CLI 和 LaunchAgent plist、执行 ad-hoc 签名并生成 ZIP。
- `LocalUserNotificationSink` 使用确定性事件 ID 安排 macOS 本地通知；App 只在用户点击后请求 alert/sound 权限。
- `SMAppService.agent(plistName:)` 注册、停用和查询 bundle 内的 LaunchAgent；后台每 900 秒运行一次内置 CLI。
- App 同时保留严格 JSON outbox，本地通知不会改变 gateway envelope，也不能指定收件人。

## 发布前必须完成

- 在完整 Xcode CI 中通过 build、test 和本地 app bundle 验证。
- 在干净 macOS 14+ 账户中验证：首次启动、通知授权/拒绝、登录项批准、重启、睡眠唤醒、停用和卸载。
- 验证嵌入 CLI 在 LaunchAgent 环境中能读取同一 Application Support、Keychain 和通知授权；失败必须在 App 中可见，不能静默。
- 完成 paired-self 真实 iMessage sender，或在 beta Release notes 中明确只提供本地通知并把 iMessage 保持为后续可选 companion。两种方案必须在发布前二选一，不能继续写成模糊能力。
- 增加 App 图标、最终版本号、架构清单、ZIP SHA-256 和从 v0.1 的升级/卸载说明。

## 不在本轮默认启用

- 不自动读取 Messages 数据库或联系人。
- 不允许 outbox 指定收件人。
- 不自动安装或信任自签名证书。
- 不提交 Apple 公证，不声称通过 Gatekeeper；是否购买 Apple Developer Program 在 beta 使用反馈后决定。
