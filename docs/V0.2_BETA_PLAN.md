# v0.2.0-beta 发布候选计划

目标是让愿意从可信源码构建的 macOS 用户获得一个可拖入 Applications 的 `iMM.app`，并能在本人明确授权后收到本地通知和启用后台检查。它仍不冒充 Developer ID 签名、公证或 Mac App Store 产品。beta 目前仍是开发分支，未发布公开二进制。

## 已进入开发分支

- `scripts/build-local-app.sh` 构建标准 app bundle、嵌入 `market-message-cli`/`iMM-gateway`、两个 LaunchAgent plist，并优先嵌入已验证的 `AppIcon.icns`（无正式资源时回退到 `AppIcon-1024.png` 开发资源）；随后执行嵌套 ad-hoc 签名并生成 `iMM-v0.2.0-beta-local.zip` 及 `.zip.sha256`。
- `scripts/install-local-app.sh` 以 staging + 恢复路径替换一个明确的 app 目标；`scripts/uninstall-local-app.sh` 按 gateway→monitor 顺序对精确的 per-user label 执行 `launchctl bootout`，默认保留 Application Support，`--remove-data` 才能删除明确数据目录。
- macOS CI 在完整 Xcode 中验证 bundle/plist、嵌套 ad-hoc 签名、ZIP 内容和 SHA-256，并上传三天内过期的 Actions artifact；workflow 不签名、不公证、不发布。
- `LocalUserNotificationSink` 使用确定性事件 ID 安排 macOS 本地通知；App 只在用户点击后请求 alert/sound 权限。
- `SMAppService.agent(plistName:)` 分别注册、停用和查询 bundle 内的 monitor 与 gateway LaunchAgent；monitor 约每 900 秒运行一次内置 CLI，gateway companion 约每 30 秒处理一次 paired-self outbox。
- App 同时保留严格 JSON outbox，本地通知不会改变 gateway envelope，也不能指定收件人。

## 发布前必须完成

- 在完整 Xcode CI 中通过 build、test、本地 app bundle、ZIP 和 SHA-256 验证；artifact 下载后仍需在真实 Mac 验收。
- 正式候选必须用完整 Xcode `iconutil` 从经过审查的 `Packaging/AppIcon.iconset` 生成 `Packaging/AppIcon.icns`，在 bundle 中嵌入并验证；若 `iconutil` 失败或 `.icns` 缺失，release gate 必须停止，不能以 PNG 改名。
- 在干净 macOS 14+ 账户中验证：首次启动、通知授权/拒绝、登录项批准、重启、睡眠唤醒、停用和卸载。
- 验证嵌入 CLI 在 LaunchAgent 环境中能读取同一 Application Support、Keychain 和通知授权；失败必须在 App 中可见，不能静默。
- 已有 paired-self 真实 iMessage sender，可由 App 明确点击“发送一次”或 `iMM-gateway --send` 触发；发布前必须在真实 Mac 验证 Apple Events 授权、发送失败/重试和送达边界。正确 target 的实机送达不等于所有 target 可送达；`osascript` exit 0 也不是 delivery receipt，不能把打包 helper 或 plist 当成已验证的自动发送服务。
- 完成 App 图标 `.icns`、最终版本号、架构清单、ZIP SHA-256 和从 v0.1 的升级/卸载说明；操作步骤见 [`V0.2_UPGRADE.md`](V0.2_UPGRADE.md)。

## 不在本轮默认启用

- 不自动读取 Messages 数据库或联系人。
- 不允许 outbox 指定收件人。
- 不自动安装或信任自签名证书。
- 不提交 Apple 公证，不声称通过 Gatekeeper；是否购买 Apple Developer Program 在 beta 使用反馈后决定。

## 当前未验证项

以下项目不能由本地 CommandLineTools 或 CI 的静态 bundle 检查推断完成，必须在真实 Mac 上记录日期、macOS 版本、架构和结果：通知允许/拒绝后的界面状态、系统设置中的登录项批准、重启后的后台运行、睡眠/唤醒后的首次检查、App 内停用与 `launchctl` 状态、从 v0.1 数据升级、保留/删除用户数据的卸载、Keychain 清理、Gatekeeper 以及 `.icns` Finder 显示。发布前任何未完成项都必须保持“未验证”，不能用 CI 绿灯替代。
