# iMarketMessage（iMM）两个一周发布节奏

这份节奏用于两个独立的一周窗口：先发布 `v0.1.0-alpha`，再在 alpha 反馈已归档、beta 实现证据齐全后启动 `v0.2.0-beta`。每个窗口均用相对日 `D-6` 至 `D0`，不承诺固定日历日期；证据未齐时暂停或顺延，不修改文案掩盖缺口。

## 统一发布约束

- 项目名称：iMarketMessage；App 名：iMM；目标平台：macOS 14+。
- 定位：本地优先的行情提醒工具。所有公开文案都要保留“不是投资建议”以及数据可能延迟、缺失或修订的边界。
- `v0.1.0-alpha`：源码、截图、CI、开发者运行说明。它只评估本地规则并写入 outbox，不安装 gateway、不发送真实 iMessage、不读取 Messages 数据库或联系人，也不承诺签名 App/DMG。
- `v0.2.0-beta`：已包含通用 paired-self iMessage gateway、App 内配对/手动发送、明确授权的 monitor 与 gateway 后台注册；签名 App 和 DMG 仍需实现并提供证据。`--dry-run` 是只读预览，不代表没有真实 sender；每项只有在证据齐全后才能在 D0 文案中使用完成时态。
- 所有外部链接使用占位符，至少替换：`[仓库链接：待填]`、`[发布日期：YYYY-MM-DD]`、`[截图链接：待填]`、`[CI 链接：待填]`、`[开发运行说明链接：待填]`。
- 同一天需要两条 X 时，安排在相隔至少 8 小时的两个时段，不在短时间内连发；其余日保持一条或不发。

## `v0.1.0-alpha` 一周窗口（D-6 至 D0）

D0 是 alpha 公开发布日。以下安排使用 8 条 alpha 文案，最多一天两条；每条文案编号对应 [alpha X 单条文案](v0.1-alpha-x-posts.md)。

| 相对日 | 公开动作 | 同步核对/留存的证据 |
|---|---|---|
| D-6 | 冻结范围和不做事项；发布第 1 条（项目定位）。 | 版本范围、alpha 限制原文、日期占位符。 |
| D-5 | 校对 README、开发命令和前置条件；发布第 2 条（规则能力）。 | 支持环境命令、规则引擎和测试指针。 |
| D-4 | 准备脱敏截图并核对 CI；发布第 3 条（数据源与风险）。 | 截图清单、替代文字、CI 运行记录。 |
| D-3 | 复核隐私、安全和 outbox 边界；发布第 4 条（本地优先与隐私）。 | `PRIVACY.md`、`SECURITY.md`、协议和权限检查。 |
| D-2 | 完成构建/测试和候选包；分两个时段发布第 5 条（开发运行）和第 6 条（alpha 发布包）。 | 构建、测试、临时目录清理、发布包内容清单。 |
| D-1 | 做 release candidate 和最终事实核对；发布第 7 条（iMessage 交接边界）。 | [发布前事实核对表](pre-release-fact-checklist.md) 的必选项和链接检查。 |
| D0 | 仅在所有 alpha 证据齐全后发布版本；发布第 8 条 D0 文案。 | 发布页、仓库、截图、CI、开发说明的最终链接。 |

如果 D-2 的构建、截图或 CI 证据不完整，不发布第 6 条或 D0 文案，直接暂停窗口并补证据；不把计划时态改成完成时态。

## `v0.2.0-beta` 一周窗口（D-6 至 D0）

beta 窗口只有在以下启动闸门全部满足后才开始：alpha 已发布且反馈已归档；paired-self gateway（含真实 sender 和 process accepted≠delivery receipt 的风险记录）、两个后台服务的安装/卸载、签名 App、DMG 均有实现证据和可复核记录。当前签名、DMG 及重启/睡眠/卸载实机证据仍不足，因此不预设 beta 日历日期。以下安排使用 12 条 beta 文案，前 11 条保持计划/候选时态；第 12 条仅在全部证据齐全后使用。

| 相对日 | 公开动作 | 同步核对/留存的证据 |
|---|---|---|
| D-6 | 分两个时段发布第 1 条（变更范围）和第 2 条（paired-self 定义）。 | alpha 反馈归档；配对策略和拒绝任意收件人的测试证据。 |
| D-5 | 分两个时段发布第 3 条（队列协议）和第 4 条（独立权限边界）。 | JSON 字段、幂等 ACK、权限边界和失败处理记录。 |
| D-4 | 分两个时段发布第 5 条（后台安装）和第 6 条（签名/DMG 核验）。 | 安装、卸载、回滚、签名验证和 DMG 校验记录。 |
| D-3 | 分两个时段发布第 7 条（本地数据）和第 8 条（行情风险）。 | 隐私、安全、数据源和 beta 限制核对。 |
| D-2 | 分两个时段发布第 9 条（候选范围）和第 10 条（安全试用边界）。 | 候选条件、测试数据、paired-self 目的地、错误 target 风险和不把 process accepted 写成 delivery receipt 的记录。 |
| D-1 | 发布第 11 条（既有 gateway 适配关系）；完成 beta release candidate 事实核对。 | 适配、回滚、权限、发布链接和 [发布前事实核对表](pre-release-fact-checklist.md)。 |
| D0 | 仅在所有实现、签名、DMG、权限和链接证据齐全后发布第 12 条 D0 文案；否则不发布。 | 发布页、签名验证、DMG 校验、安装说明和已知限制。 |

beta 不与 alpha 同日启动，也不因候选招募需要而提前宣称功能完成。签名或 DMG 尚未可核验时，任何 beta 文案都不能写“已签名/已提供”；候选入口使用 `[候选登记链接：待填]`，不要求评论、转发、私信或提供个人联系方式。

## 发布日收口

发布前先替换所有占位符，再逐条对照 [发布前事实核对表](pre-release-fact-checklist.md)。发布包只保留源码、必要文档、截图和经确认的构建产物；临时 scratch 目录、日志、测试 outbox、截图原稿和含个人信息的副本在各自 D0 前清理。
