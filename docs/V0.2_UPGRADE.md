# v0.2.0-beta 本地安装、升级与卸载

这份说明只针对从可信源码构建的本地 `iMM.app`。当前产物是 ad-hoc 签名，不是 Developer ID 签名、公证或可绕过 Gatekeeper 的公开发行版。安装脚本不会替用户注册 monitor/gateway 服务，也不会删除用户数据。bundle 内的 `iMM-gateway` 只有显式 `--send` 才能消费 paired-self outbox。

## 安装前检查

1. 使用完整 Xcode（不是仅 CommandLineTools）构建，并确认脚本生成的三个文件：

   ```text
   dist/iMM.app
   dist/iMM-v0.2.0-beta-local.zip
   dist/iMM-v0.2.0-beta-local.zip.sha256
   ```

2. 对 ZIP 做校验；校验通过只说明文件未被意外改动，不说明签名、公证或来源可信：

   ```sh
   (cd dist && shasum -a 256 -c iMM-v0.2.0-beta-local.zip.sha256)
   ```

3. 确认 `~/Library/Application Support/MarketMessage/` 下的 `rules.json`、`runtime-state.json` 和 `Outbox/` 是否需要保留。安装和升级默认保留它们；如果需要备份，应由用户选择一个明确的备份目录并在任务完成后自行管理，不要把 API key 或真实 outbox 上传到仓库。

## 首次安装

默认安装到当前用户的 `~/Applications/iMM.app`：

```sh
scripts/install-local-app.sh --app dist/iMM.app
open "$HOME/Applications/iMM.app"
```

安装到系统 `/Applications` 时必须显式指定目录，并按脚本提示确认（可能需要 Finder/终端的系统权限）：

```sh
scripts/install-local-app.sh --app dist/iMM.app --destination /Applications
open /Applications/iMM.app
```

脚本在替换前会校验 Info.plist、monitor/gateway 内嵌 LaunchAgent plist 和 ad-hoc 签名；如果当前用户的 `com.imarketmessage.monitor` 已加载，会只对 `gui/$(id -u)/com.imarketmessage.monitor` 执行 `launchctl bootout`。脚本不会调用 `SMAppService.register()`，也不会自动启用登录项或 gateway sender。

首次打开 App 后，按需要逐项操作：

- 点击“请求通知权限”，分别记录允许和拒绝的结果；拒绝时到“系统设置 → 通知”确认状态可见。
- 若需后台检查，在 App 内点击启用，按提示到“系统设置 → 通用 → 登录项”批准；回到 App 确认状态和最近后台检查时间。
- 若需发送 paired-self outbox，先用 `--dry-run` 检查，再由用户明确运行 `iMM-gateway --send`；处理 Messages 的 Apple Events 允许/拒绝提示，并确认没有传入 recipient/电话号码/chat ID。
- 不需要后台时，在 App 内点击“停用后台监控”。不要只删除 app 文件而跳过这一步。

## 升级与回滚

升级不会迁移或重写规则格式以外的用户数据，也不会删除 Keychain。先退出正在运行的旧 App，并在旧 App 内点击“停用后台监控”；再用新构建替换同一安装位置：

```sh
scripts/install-local-app.sh --app dist/iMM.app --destination "$HOME/Applications"
open "$HOME/Applications/iMM.app"
```

脚本会把旧 app 暂存到同一目录下的临时 staging 路径，校验新 app 成功后再替换；替换失败时尽量恢复旧 app。新 App 不会自动恢复后台授权，需用户在 UI 中检查并重新批准。升级后验证：规则数量、最近状态、outbox 权限（目录 `0700`、文件 `0600`）、通知状态、登录项状态和 `background-health.json`。

如果升级后出现问题，先在新 App 内停用后台，再用此前的 `iMM.app` 按同一命令安装回原目标；只要不使用卸载的 `--remove-data`，规则和 outbox 会留在原位置。

## 卸载

卸载前先在 App 内点击“停用后台监控”，并确认登录项不再显示为已启用。脚本默认只删除明确的 app 路径，保留 Application Support 和 Keychain：

```sh
scripts/uninstall-local-app.sh --app "$HOME/Applications/iMM.app"
```

若安装在 `/Applications`，传入明确路径：

```sh
scripts/uninstall-local-app.sh --app /Applications/iMM.app
```

脚本会显示目标并要求确认，然后对当前用户的精确 monitor/gateway 服务标签执行 `launchctl bootout`（若仍在运行），最后删除该 `iMM.app`。它不会删除 `~/Library/Application Support/MarketMessage`，也不会删除 Keychain API key；需要时先在 App 内删除 key，或在“钥匙串访问”中手动删除对应项目。

只有明确选择删除用户数据时才使用：

```sh
scripts/uninstall-local-app.sh --app "$HOME/Applications/iMM.app" --remove-data
```

该选项只删除精确目录 `~/Library/Application Support/MarketMessage`，包括规则、运行状态和 outbox；它不会扩大到 `~/Library` 或其他应用数据。`--yes` 仅适合已核对目标路径的自动化场景：

```sh
scripts/uninstall-local-app.sh --app "$HOME/Applications/iMM.app" --remove-data --yes
```

如果卸载后“登录项”仍显示旧项目，不要删除其他厂商条目；重新打开仍存在的旧 App 并点击停用，或在系统设置中只移除 `com.imarketmessage.monitor` 对应项，再用 `launchctl print gui/$(id -u)/com.imarketmessage.monitor` 确认服务不存在。

## 真实 Mac 验收记录

CI 只能证明源码、bundle/plist、ad-hoc 签名、ZIP 和 SHA-256 检查通过。发布前必须在 macOS 14+ 干净账户逐项记录：通知允许、通知拒绝、登录项批准、重启、睡眠/唤醒、后台停用、升级回滚、卸载后服务状态、保留/删除数据、Keychain 清理以及 Finder 图标显示。当前未完成的项目必须标记“未验证”，不能把 CI artifact 或 ad-hoc 签名写成 Developer ID/公证结果。
